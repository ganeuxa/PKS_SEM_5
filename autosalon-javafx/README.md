# Автосалон: заявки на тест-драйв (КР 2, JavaFX)

Настольное JavaFX-приложение для базы данных `autosalon` из [КР 1](../autosalon-testdrive).
Приложение подключается к PostgreSQL напрямую через **JDBC** (без REST API).

- **Основная сущность:** заявка на тест-драйв (`test_drive_requests`) — полный CRUD, смена статуса, поиск,
  фильтры, сортировка, экспорт, карточка со связанными данными.
- **Вторая сущность:** клиент (`clients`) — полный CRUD, поиск, экспорт, заявки выбранного клиента.
- **Справочник:** автомобили (`cars`) — выбираются в форме заявки из выпадающего списка (только «В наличии»).
- **Архитектура:** `FXML (View) -> Controller -> Service -> Repository (JDBC) -> PostgreSQL`.

## Что нужно установить

| Программа | Зачем |
|---|---|
| **JDK 21** или новее | сборка и запуск (Java 8 не подойдёт: `java -version` должна показать 21+) |

## 1. База данных

**Вариант А — локальный PostgreSQL (как в КР 1).** Если база `autosalon` уже создана в КР 1, ничего делать не нужно.
Иначе выполните скрипты КР 1 (из папки `pks-5sem`):

```bash
psql -U postgres -f autosalon-testdrive/sql/01_create_database.sql
```

```bash
psql -U postgres -d autosalon -f autosalon-testdrive/sql/02_schema_and_data.sql
```

Пароль пользователя `postgres` укажите в `src/main/resources/database.properties` (`db.password`).

**Вариант Б — база в Docker.** Запустите Docker Desktop и в папке `autosalon-javafx` выполните:

```bash
docker compose up -d --wait
```

Контейнер `autosalon-db` при первом запуске создаст базу `autosalon` и выполнит скрипт КР 1
`02_schema_and_data.sql`. С компьютера база доступна на порту **55433**. В `database.properties`
закомментируйте строки варианта 1 и раскомментируйте строки варианта 2.

Проверка: `docker compose ps` — контейнер в состоянии `healthy`. Остановка без потери данных: `docker compose down`
(не добавляйте `-v`, он удаляет volume с данными).

> Скрипт `02_schema_and_data.sql` пересоздаёт таблицы с тестовыми данными — удобно выполнить его перед защитой.

## 2. Запуск приложения

**IntelliJ IDEA:** *File → Open* → папка `autosalon-javafx` → дождаться загрузки Maven-зависимостей →
открыть `src/main/java/ru/mirea/autosalon/Launcher.java` → ▶ рядом с `main`.
(Запускать нужно `Launcher`, а не `AutosalonApp`: см. комментарий в классе.)

**Командная строка** (в папке `autosalon-javafx`):

```bash
mvnw.cmd javafx:run
```

или двойной щелчок по `run.bat`. При первом запуске `mvnw` сам скачает Maven 3.9.11.

Другие команды: `mvnw.cmd test` — 27 модульных тестов, `mvnw.cmd clean package` — сборка jar.

Если в заголовке окна горит красное «Нет подключения», проверьте, что PostgreSQL/контейнер запущен и параметры в
`database.properties` верные, затем нажмите «Переподключиться».

## Сценарий демонстрации

Перед защитой выполните `02_schema_and_data.sql` (или `docker compose down -v` и `up`). «Завтра» — день после запуска скрипта.

1. **Запуск:** Docker/PostgreSQL → `mvnw.cmd javafx:run`. В заголовке — зелёная метка подключения.
2. **Таблица и связанные данные:** выбрать заявку — справа карточка клиента и автомобиля.
3. **Валидация:** «Добавить» → сразу «Сохранить» → «Выберите значение в поле «Клиент»», поле подсвечено.
   Длительность `abc` → «должно быть целым числом»; `200` → «допустимы значения от 15 до 120»; время `25:00`;
   дата `31.02.2026`.
4. **Бизнес-правила:** клиент Иванов, Toyota Camry, завтра 10:00 → «автомобиль уже занят (заявка №8)».
   Время 12:00 → заявка создана и выделена в таблице. 20:30 на 60 мин → «вне часов работы».
5. **Статус:** «Сменить статус» новой заявки → «Подтверждена». Заявка №1 (завершена) → «заявка закрыта».
   «Изменить» для закрытой заявки → сообщение, форма не открывается.
6. **Удаление:** «Удалить» → подтверждение → «Отмена» / «Удалить».
7. **Поиск, фильтры, сортировка:** поиск `camry`, `иван`, `916`; статус «Новая»; марка «Kia»; период; «Только предстоящие»;
   сортировка «По ФИО клиента» + «По убыванию»; щелчок по заголовку «Статус».
8. **Клиенты:** добавить клиента младше 18 лет → ошибка; с телефоном существующего клиента → ошибка уникальности;
   удалить клиента с заявками → «нельзя удалить». Выбрать клиента — внизу его заявки.
9. **Статистика:** кнопка «Статистика» — карточки, таблица, графики. Создать заявку и вернуться — числа изменились.
10. **Экспорт:** отфильтровать заявки → «Экспорт в CSV» → выбрать путь → открыть файл в Excel.
11. **Ошибка подключения:** `docker compose stop` (или остановить службу PostgreSQL) → «Обновить» → понятное сообщение,
    приложение работает дальше. Запустить базу → «Переподключиться».

## Пояснения к защите

### Как запускается приложение
`Launcher.main` → `Application.launch(AutosalonApp.class)` → JavaFX создаёт главное окно и вызывает
`AutosalonApp.start(Stage)`. В `start`: `AppContext.create()` читает `database.properties` и создаёт репозитории и сервисы,
`FXMLLoader` загружает `main-view.fxml`, создаётся `Scene` с CSS, окно показывается, затем
`MainController.connectAndLoad()` проверяет подключение и загружает данные.

### Stage, Scene, Node
- **Stage** — окно (главное окно приложения, окна диалогов).
- **Scene** — содержимое окна, корень дерева элементов; к сцене подключается CSS.
- **Node** — любой элемент в дереве: контейнеры (`BorderPane`, `VBox`, `GridPane`) и элементы управления
  (`Button`, `TableView`, `Label`). Контейнеры — тоже узлы, поэтому интерфейс — это дерево узлов.

### FXML и Controller
- FXML описывает **как выглядит** интерфейс (разметка), Java-контроллер — **что он делает**. Разметку можно менять, не трогая логику.
- `fx:controller="...RequestsController"` — какой класс создать контроллером.
- `fx:id="requestTable"` — элемент внедряется в поле `@FXML private TableView<...> requestTable`.
- `onAction="#handleAdd"` — при нажатии вызывается метод `@FXML private void handleAdd()`.
- После внедрения полей FXMLLoader вызывает `initialize()` — там настраиваются столбцы, слушатели, привязки.
- `fx:include` подключает вкладки из отдельных файлов; их контроллеры попадают в поля
  `requestsController`, `clientsController` главного контроллера (`fx:id` + `Controller`).
- Контроллеры получают сервисы через конструктор: `ViewLoader` задаёт `controllerFactory`, которая передаёт `AppContext`.

### TableView и ObservableList
```
ObservableList<TestDriveRequest> requests   ← все заявки из БД (requests.setAll(service.getAll()))
  └ FilteredList                            ← поиск и фильтры: setPredicate(service.buildFilter(...))
      └ SortedList                          ← comparator привязан к comparator таблицы
          └ TableView.setItems(...)
```
`ObservableList` сообщает подписчикам о каждом изменении, поэтому таблица перерисовывается сама:
после добавления, изменения или удаления контроллер вызывает `reload()` → `requests.setAll(...)`, и таблица обновляется
без ручной перерисовки. В столбцах `cellValueFactory` говорит, какое значение взять из объекта, а `cellFactory` —
как его показать (дата в формате ДД.ММ.ГГГГ ЧЧ:ММ, цветной статус). Значение хранится «как есть» (`LocalDateTime`, enum),
поэтому сортировка идёт по значению, а не по тексту.

### Сортировка
При щелчке по заголовку `TableView` меняет свой `comparatorProperty`. Он привязан к `SortedList`
(`sortedRequests.comparatorProperty().bind(requestTable.comparatorProperty())`), и список пересортировывается.
У текстовых столбцов задан `Formats.russianOrder()` (правила русского алфавита), у статуса — порядок констант enum
(жизненный цикл). Список «Сортировка» делает то же самое программно: `requestTable.getSortOrder().setAll(столбец)`.

### Поиск и фильтрация
Условие собирает сервис: `TestDriveRequestService.buildFilter(RequestFilter)` объединяет условия через
`Predicate.and(...)`. Поиск без учёта регистра ищет текст в ФИО, марке/модели, VIN и комментарии, а цифры — в телефоне.
Контроллер только передаёт результат в `filteredRequests.setPredicate(...)`. Слушатели на полях фильтра применяют
его сразу при вводе. Проверено тестами `RequestFilterTest`.

### Где бизнес-логика и где работа с данными
- Бизнес-правила — в `service` (12 правил КР 1: возраст ≥ 18, уникальность, расписание 09:00–21:00, занятость автомобиля,
  лимит 3 активных заявки, переходы статусов, запрет удаления клиента с заявками и т.д.).
- SQL — только в `repository/jdbc` (`PreparedStatement` с параметрами `?`, `try-with-resources`, JOIN для заявки с клиентом и автомобилем).
- Контроллеры: получить действие пользователя → вызвать сервис → показать результат или ошибку.

### Проверка пользовательских данных
1. **Форма** (`AbstractFormController`): обязательность, целое число и диапазон, существующая дата (`ResolverStyle.STRICT`),
   формат времени ЧЧ:ММ, длина строк, выбран ли объект в `ComboBox`. Неверное поле подсвечивается классом CSS `field-error`.
2. **Сервис**: формат телефона/email/ВУ, возраст, уникальность (запрос в БД), существование клиента и автомобиля,
   правила расписания и статусов.
3. **База данных**: `NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY` — последний рубеж.

При ошибке окно формы не закрывается: обработчик кнопки «Сохранить» вызывает `event.consume()`, а текст ошибки
показывается под полями.

### Обработка исключений
Репозитории переводят `SQLException` в `DataAccessException`, сервисы бросают `ValidationException`, `BusinessException`,
`EntityNotFoundException`. Контроллеры ловят `AutosalonException` и вызывают `Alerts.showError(...)`: заголовок выбирается
по типу исключения («Некорректные данные», «Нарушение бизнес-правила», «Нет подключения к базе данных»), текст — из сообщения.
Непредвиденные ошибки ловит `Thread.setDefaultUncaughtExceptionHandler` в `AutosalonApp`: пользователь видит сообщение,
а stack trace пишется в журнал (slf4j). Пустых `catch` нет.

### Статистика
`StatisticsService.calculate(...)` (из КР 1) считает показатели через Stream API: `groupingBy` + `counting` по статусам и
маркам, `average` для длительности и возраста, `filter` + `count` для активных и предстоящих. Вкладка пересчитывает статистику
при каждом открытии. Карточки строятся в коде (`StatisticsController.showCards`), графики — `PieChart` и `BarChart`.

### Экспорт
«Экспорт в CSV» берёт текущий `SortedList` (то, что видно в таблице), `FileChooser.showSaveDialog` возвращает путь,
выбранный пользователем, `ExportService` формирует строки, `CsvWriter` записывает файл в UTF-8 с BOM и разделителем `;`
(чтобы русский Excel открыл его правильно). Значения с `;`, кавычками или переносами строк экранируются по правилам CSV.

### Где хранится пароль БД
В `src/main/resources/database.properties`, а не в коде. `DatabaseManager.fromConfig()` читает его из ресурсов,
а если рядом с местом запуска лежит свой `database.properties` — берёт значения из него.
